# KnockoutOrNot after the move — current state and how to change things

Written 2026-09-02, the day the site moved to knockoutornot.com. Every statement here was checked against the repository and the live site on that day. When something changes, update this file; it is meant to be the first thing to read before touching the project.

Companion documents: `Domain_Migration.md` (the step-by-step record of the move, with checklists), `Deployment_History.md` (plain-language log of what changed on the live site and when), `Codebase_Explainer.md` (a longer tour of the code), `CLAUDE.md` (the working rules Claude follows in this repository).

---

## 1. What was done, in short

The site used to be served by GitHub Pages at `deadalus5.github.io/knockout-or-not/`. It is now served by Cloudflare at **https://knockoutornot.com**. The site's files are uploaded to Cloudflare by the same GitHub workflow that already refreshed the fight data, so the automatic updates after each fight card continue exactly as before. The old GitHub address still exists, but only as a signpost: every old link forwards to the same page on the new domain, and it quietly removes the app's old offline helper from returning visitors' browsers.

Along the way three small code fixes shipped: the page's icon links became absolute (a directly opened event page used to request a missing icon), the build stopped producing a GitHub-Pages-only `404.html`, and the data loader now refuses anything that is not JSON (Cloudflare answers a request for a missing file with the app page and a success status, so the loader has to check what it received). A cookie-free visitor counter (Cloudflare Web Analytics) was added. Nothing about the fight data, the spoiler protections, or the way the app looks and behaves changed.

## 4. How a change reaches the live site

Everything is driven by pushes to the `main` branch and by GitHub's schedule. There is no manual upload step anywhere.

1. **Edit** files locally, then run the checks from the repository root:
   ```bash
   npm run typecheck && npm test && npm run audit && npm run build && npm run smoke
   ```
   Every one of these must pass. `npm run audit` scans the published data for spoilers; `npm run smoke` boots the built site locally and checks the app shell, the install file, the offline helper, the data files and the spoiler patterns.
2. **Commit and push** to `main`.
3. **GitHub Actions** runs two workflows on every push:
   - `CI` repeats the checks above from a clean install.
   - `Refresh data & deploy` publishes: it builds the site, smoke-tests the build, and uploads it to Cloudflare (job `deploy-workers`). On pushes it also republishes the forwarding page to the old GitHub address (job `pages-redirect`). The data-refresh job is skipped on pushes.
   The publish finishes about a minute after the push. The upload is all-or-nothing: if it fails, the previous version keeps serving.
4. **Verify** at `https://knockoutornot.com` (a hard refresh, or a private window, avoids your own browser's cached copy).
5. **Log it** in `Deployment_History.md` in plain language (newest entry first).

**Data refreshes** run on their own: Sunday 12:00 and 18:00 UTC, Monday 09:00 UTC, plus the Saturday-night watcher (`watch-events.yml`) that polls ESPN's scoreboard every ten minutes during fight windows and triggers a refresh when a finished event is missing. A refresh fetches new results, runs the spoiler audit, commits the data, then publishes. To trigger one by hand: GitHub → Actions → "Refresh data & deploy" → Run workflow, or `gh workflow run refresh-and-deploy.yml`.

## 5. Where to make each kind of change

| You want to change… | Edit… | Notes |
|---|---|---|
| Wording, layout, colours, the reveal table | `web/src/` (`components/FightTable.tsx`, `pages/`, `styles.css`) | Keep to the existing colour tokens in `styles.css`. Run the web tests |
| How fights are scored or merged | `pipeline/src/score/`, `pipeline/src/merge/` | Then `npm run data:refresh` locally, `npm run audit`, and commit the regenerated data with the code |
| What data is published | `shared/src/schema.ts` and `pipeline/src/emit/sanitize.ts` | Read the "spoiler boundary" section of `CLAUDE.md` first. Adding a field also breaks already-cached copies of the app until they update |
| Browser caching or safety headers | `web/public/_headers` | Keep `Cache-Control` out of the `/*` block; Cloudflare joins duplicate headers with commas |
| How unknown addresses are served | `web/wrangler.jsonc` | Do not add `main`, `run_worker_first` or `cache` (see section 7) |
| The forwarding page at the old address | `web/pages-redirect/index.html` and `sw.js` | Published only on pushes |
| Refresh schedule, publish steps | `.github/workflows/refresh-and-deploy.yml`, `watch-events.yml` | The watcher dispatches the deploy workflow by its file name; do not rename that file casually |
| Analytics snippet | `web/index.html` | The token in it is a public site id, not a secret |
| App name, icons, colours of the installed app | `web/vite.config.ts` (manifest section) and `web/public/icons/` | |
| The Cloudflare publishing tool version | `web/package.json` (`wrangler`) **and** `wranglerVersion` in the workflow | Keep the two identical |

## 6. Settings that live outside the repository

These are not in git. Change them in the dashboards; note the change in `Deployment_History.md`.

**Cloudflare** (dash.cloudflare.com)
- **Domain attachment**: Workers & Pages → knockoutornot → Settings → Domains & Routes. `knockoutornot.com` is attached here. It is deliberately *not* declared in `web/wrangler.jsonc` (section 7).
- **www forwarding**: knockoutornot.com → DNS → Records: an `A` record `www` → `192.0.2.0`, proxied (a placeholder; nothing lives at that address). knockoutornot.com → Rules → Overview: one Redirect Rule, condition "Hostname equals `www.knockoutornot.com`", action Dynamic redirect to `concat("https://knockoutornot.com", http.request.uri.path)`, status 301, preserve query string.
- **Always Use HTTPS**: knockoutornot.com → SSL/TLS → Edge Certificates. On.
- **Web Analytics**: Web Analytics → knockoutornot.com → Manage site. "JS snippet" mode.
- **DNSSEC**: Domain Registration → Manage Domains → knockoutornot.com → Configuration. Enabled 2026-09-02. Do not disable it or move the nameservers without waiting out the period Cloudflare specifies.
- **API token for publishing**: Manage Account → API Tokens. The publish needs the permission `Account · Workers Scripts · Edit` and nothing else. To rotate: ⋯ → Roll, then paste the new value into GitHub (below).
- **Account and zone identifiers** (not secrets): Account ID `e7077b350de6ebf63f73fe4407bda6ce`, Zone ID `4e19e535f8585efc4c07ba96379640c4`, workers.dev subdomain `rbwcontent`.

**GitHub** (github.com/deadalus5/knockout-or-not)
- **Secrets**: Settings → Environments → `cloudflare` → Environment secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`. Only workflow jobs that declare `environment: cloudflare` and run on `main` can read them. Values can be replaced but never viewed. Environment secrets work on the free plan only while the repository is public.
- **GitHub Pages** (the old address): Settings → Pages. Source "GitHub Actions". **Never set a custom domain here** (section 7).
- **Website field**: set to `https://knockoutornot.com`.

## 7. Rules that must not be broken

1. **Never add `main`, `assets.run_worker_first` or `cache` to `web/wrangler.jsonc`.** Any of them turns free, unlimited static-asset requests into metered Worker requests with a daily cap.
2. **Keep the domain attached in Cloudflare, not declared in `wrangler.jsonc`.** Declaring `routes` makes every publish query zone settings that the publishing token cannot access; that exact failure happened once on 2026-09-02 (the site still updated, but the job went red). If you ever want it declared in code, first give the token `Zone · Workers Routes · Edit` on knockoutornot.com.
3. **Never set a custom domain on the GitHub Pages project.** GitHub would then redirect the old `sw.js` address, and browsers that still hold the old app could never pick up the clean-up helper.
4. **Never put a token in a file in this project.** `.gitignore` guards `.env`, `.dev.vars` and `.wrangler/`, but the rule is the real protection.
5. **The spoiler boundary** (`CLAUDE.md`): winner data never enters the published files; `npm run audit` and `npm test` must be green before committing regenerated data.
6. **Don't hand-edit generated data** (`web/public/data`, `pipeline/data`).

## 8. Running it locally

```bash
npm ci                     # install (once, and after dependency changes)
npm run dev                # development server at http://localhost:5173
npm run build && npm run preview   # the production build, served locally at /
npm test                   # all tests
```
A local `wrangler` is installed with the project; `cd web && npx wrangler deploy --dry-run` validates the Worker config without any credentials. Publishing from a laptop is not part of the setup; pushes to `main` publish.

## 9. Health, failures, and undoing things

- **Where to look**: GitHub → Actions (every run, with logs); Cloudflare → Workers & Pages → knockoutornot (deployments list and request metrics); Cloudflare → Web Analytics (visits).
- **A red "Refresh data & deploy" run** means the publish (or a data refresh) failed. The site keeps serving the last good version. Open the run, read the failed step. If it is the "Upload to Cloudflare" step with an authentication error, the token was revoked or changed: roll it in Cloudflare and paste the new value into the GitHub environment secret. GitHub emails you about failed runs unless you have turned that off.
- **Roll back without touching code**: Cloudflare → Workers & Pages → knockoutornot → Deployments → ⋯ on an earlier version → Rollback. Note this also rolls the published fight data back to that version until the next refresh runs.
- **Roll back with code**: `git revert <commit>` and push; the workflow republishes.
- **A missing file** on the new host returns the app page with status 200 rather than 404. The data loader detects this and shows the normal "could not load" message. When checking the site by hand, look at the content type of a response, not only its status.
- **Data sources breaking** behaves as before: a Wikipedia parsing failure fails the run loudly and the site keeps the last good data; an ESPN failure is logged and skipped.

## 10. Known limitations and possible follow-ups

- Directly opened pages now return status 200 (they returned 404 on GitHub Pages), so search engines can index event pages. There is no `robots.txt` or sitemap; add them to `web/public/` if indexing should be shaped.
- The pipeline's User-Agent string still identifies the project by e-mail only (`pipeline/src/config.ts` and `.github/workflows/watch-events.yml`, two identical copies that must change together); adding the new domain is optional.
- No Content-Security-Policy header is set. If one is added to `web/public/_headers`, it must allow the analytics script from `static.cloudflareinsights.com` and inline styles used by the app.
- Anyone who installed the app to a home screen from the old address will be sent to knockoutornot.com in a browser tab when opening it; installed copies cannot be moved and must be re-added from the new domain.
- HSTS (a browser setting that remembers "always HTTPS" for the domain) is not enabled; it can be turned on later under Cloudflare → SSL/TLS → Edge Certificates, starting with a short duration.
